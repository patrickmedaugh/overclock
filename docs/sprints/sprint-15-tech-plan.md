## Movement (client only; the engine stays pure)
- **One scheduler:** the existing skippable `fx` `Tweens` queue. Input feedback (press lift, lean, drag follow, hover) goes on `ui` (never skipped). **Tap finishes:** `main.ts` adds a capture-phase `pointerdown` listener on the canvas's parent that calls `fx.finishAll()` before Pixi dispatches the tap (logs `motion_skipped`), so a tap always acts on the final board. Resize/rotate already finishes (`redrawAll`). `fx` never blocks input; every record's `scheduledMs` ≤ 600.
- **Pure planner `apps/client/src/motion.ts`** (no Pixi; pinned, ui-dev pushes the types + stub first):
  `planMotion(viewer: Side, events: readonly GameEvent[]): Flight[]`, `Flight = {kind: FlightKind; cardId: string | null /* null = drawn face down */; side: Side; from: Anchor; to: Anchor; delayMs; durationMs; land?: {counter: 'deck'|'discard'|'score'|'hand'; side: Side}}`, `Anchor = {at: 'hand'; side; index?} | {at: 'deck'|'discard'|'score'; side} | {at: 'installed'; uid} | {at: 'center'} | {at: 'drop'}`, `FlightKind = 'draw'|'install'|'play'|'showcase'|'discard'|'trash'|'score'|'steal'|'damage'|'mill'|'return'`, `motionSpan(f: Flight[]) = max(delay+duration)`. **`cardId` comes only from the viewer's projected event** (`viewEvents`), never from the view of the other seat, so a Corp install/discard/ABT mill seen by the Runner is a card back. The board resolves anchors to boxes (opponent's hand = top edge, `drop` = the release point). Runs keep their Sprint 3–12 animations (next slice).
- **Timings (`theme.timing`, Q1 A):** flight 240 ms, landing settle 110 ms (scale 0.92→1, `outBack`; total ≤ 360), showcase 180 → center, hold 150, 180 → discard (510), press lift 80 ms (scale 1.08, −10 % card height), return glide 160 ms, score tick 200 ms + glow 300 ms. **Ripple:** stagger `min(60, 260/(n−1))` ms so a batch ends ≤ 500 ms; at most 4 sprites in the air, extra cards land at once (counts still right). Lean: `leanAngle(vx px/ms, prev, dt)` pure in `handGesture.ts`, `±14°` max, eased back to 0 in ~80 ms when still. Decorative extras (settle, lean, hover) obey `framesAreSlow()` like the carousel (S-05-3).
- **Pile counts change on landing:** piles/score widgets show the pre-batch value and `pop`/tick on each `land` (pattern of S-10-5's Archives); `finishAll` lands everything, so a skipped or rotated batch ends exact.
- **Other seat's cards:** online, the other phone's moves arrive as `same` presentations: install/play flights start at the top hand area. Pass-the-phone: `Presentation.handoff` gains `missedEvents: GameEvent[]` (the next seat's projection of the actor's whole turn, collected by `HotSeat`; not saved), played as one ripple (≤ 500 ms) after the cover lifts.
- **Cost:** flights reuse the baked card textures (no new `Graphics` per flight); face-down = the shared back texture.
- **Test switch (test build only):** `?motion=instant|hold` and hook `__overclock.motion(mode)` (`normal` default, so existing specs keep exercising real motion via `waitIdle`); `hold` freezes `fx` (not `ui`) and `__overclock.advanceMotion(ms)` steps it, so specs inspect mid-flight and tap deterministically. `layout()` gains `motion: {active: number; flights: {kind, cardId: string|null, box}[]}`. New `AnimKind`s: `hand_press`, `hand_return`, `land_settle`, `showcase`, `score_tick`, `opponent_flight`, `motion_skipped`.

## Risks
- **The owner's Netlify click** is needed before the play link shows sprint builds and the APK; until then https://overcloc.netlify.app shows the last main build (no button) and the PR's Deploy Preview is the web backup.
- **Netlify credits:** if the account is on Netlify's newer credit plan, each production deploy costs credits; the `play` push runs once per code push (bursts collapse). If it bites: publish only on `workflow_dispatch` + sprint PR updates.
- **`play` history** gains ~3.5 MB per publish; the force-push leaves old commits unreachable (GitHub cleans them up). Fine for months.
- **Tap during a hand slide** acts on where the cards end up (finished first), not where they were drawn mid-slide (≤ 180 ms window).
- **Phone smoothness** at 891×296: if frames drop, settle/lean go first (S-05-3 rule), then the in-air cap drops to 2.
