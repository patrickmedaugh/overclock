Scope: S-07-1..6 (owner answers 2026-11-14: 1B, 2A tap card → buttons where Rez/Advance sit, 3A Corp rezzes assets/upgrades on its own turn outside runs, 4A PSF/Sacrificial Construct untouched, Bank Job "take all"). engine-dev (worktree, local branch `sprint-07-engine`) and ui-dev (`sprint-07-ui`) start **together**; helper branches are never pushed; the lead merges into `sprint-07`. Contract changes go through the architect. Everything below is data + generic engine code: **no card-id checks in the engine or client**.

## Card DSL v2 (`packages/cards/src/types.ts`; additive)
- Effects: `place_credits{amount}` (onto the source card), `take_credits{amount: number | 'all'}` (source card → its owner). `EffectContext` gains `uid` (source installed card).
- `CardDef` fields: `onInstall?: Effect[]` · `onTurnStart?: Effect[]` (rezzed Corp card / Runner card, at its owner's turn start) · `cardAbilities?: CardAbility[]` · `recurringCredits?: {amount, for: 'icebreaker'}` · `trashWhenEmpty?: true` · `memoryBonus?: number` · `iceRezDiscount?: number` (rezzed upgrade: ICE protecting its server, min 0) · `advanceable?: true` + `strengthPerAdvancement?: number` (ICE).
- `CardAbility = {label, when: 'click' | 'successful_run_remote', clicks, credits, requires?: 'hosted_credits', replacesAccess?: true, effects}`; `label` may hold `{gain}` (client fills it from the option). Data: Armitage `onInstall place 12`, ability click 1 "Take {gain} credits" `take_credits 2`, `requires`, `trashWhenEmpty`; Bank Job `place 8`, `successful_run_remote` "Take {gain} credits from Bank Job" `take_credits 'all'`, `replacesAccess`; Cyberfeeder `recurringCredits {1, icebreaker}`; Akamatsu `memoryBonus 1`; PAD `onTurnStart gain_credits 1`; Akitaro `iceRezDiscount 2`; Ice Wall `advanceable`, `strengthPerAdvancement 1`.

## Engine interface (pinned; E1 copies it to `packages/engine/README.md` "Sprint 7 interface")
- **State**: `Installed.hostedCredits: number` (0 default); `RunStep` += `'success'`; `RunOutcome` += `'access_replaced'`; export `RULES_VERSION = 1` (bump when an old action log would replay differently). No other new top-level field.
- **Action** (new): `{type:'activate', player, uid, ability}` — `ability` indexes `CardDef.cardAbilities`. Checks: invalid_action → game_over → not_your_turn (`waitingOn`) → bad_target (own installed, face-up card, ability exists) → wrong_phase (`click`: action phase; `successful_run_remote`: run step `success`) → no_clicks → condition_not_met (`requires` unmet) → no_credits. `use_ability` (breakers) unchanged.
- **Changed actions**: `rez` also legal in the Corp's **action phase** on an unrezzed asset/upgrade in any server (no click; ICE there = bad_target). `advance` targets agendas **or** `advanceable` ICE (face up or down); `score` stays agendas only.
- **Events** (all public): `card_rezzed{uid, cardId, server}` (asset/upgrade, after `credits_spent`) · `ability_triggered{uid, cardId, trigger: 'click'|'turn_start'|'successful_run'}` (before the effect's events) · `hosted_credits_changed{uid, credits}` (new total; install, take, spend, refill) · `rig_card_trashed{uid, cardId}` (to the Heap, face up) · `server_removed{server}` · `credits_spent.hosted?` (part paid from hosted credits).
- **Rules**: `rezCost(state, ice)` applies every rezzed `iceRezDiscount` in that server (approach option cost, `'affordable'` window and `no_credits` all use it). `iceStrength(ice)` = printed + advancements × `strengthPerAdvancement`. `memoryLimit(state)` = 4 + rig `memoryBonus`. Runner payments for breaker abilities: eligible recurring credits first (rig order), then run-only (bad publicity), then own; "can afford" counts all three. Recurring credits placed on install and refilled to `amount` at the Runner's turn start. Turn start order: `turn_started` → `onTurnStart` effects (servers order, then rig) / refills → Corp draw. **Successful run on a remote** with a usable `replacesAccess` ability → run step `success`, waiting on the Runner: options = `activate` per usable card + `pass` (= Access cards); activate → `ability_triggered`, `hosted_credits_changed`, `credit_gained`, (`rig_card_trashed`), `run_ended{access_replaced}`. Not usable (no credits / central) → no step (auto-pass). **Empty remotes** (no ICE, no content) are removed at `endRun` (after `run_ended`) and at the end of `score` → `server_removed`; ids never reused (`nextRemote` unchanged). Supersedes the Sprint 3 ruling (d).
- **View**: `InstalledView.hostedCredits` (public); `memory.limit` = `memoryLimit`; `installedOptions` now **both sides**, keyed by uid, listed off-turn with reasons: Corp = agenda `advance`/`score`, advanceable ICE `advance`, unrezzed asset/upgrade `rez`; Runner = `activate` per `click` ability. `CardOption` += `clicks?` (click cost when > 0), `gain?` (credits the option gives), `hostedPay?: {uid, amount}[]` (breaker options: who pays). Hidden info: the Runner never gets options or ids for unrezzed Corp cards; `card_rezzed` / `ability_triggered` name a card only once it is face up. `legalActions` includes all new options (AI picks from it).
- **Protocol** (additive, still v1): client `{v:1, t:'leave'}` — a seat in a lobby nobody joined: the room closes (sockets closed, storage deleted; the code then answers `no_game`). In a started game → `bad_message`. **Room restore by replay** (other build) expires the game if any logged action is rejected on replay (the log only holds accepted actions; a rules change made it diverge) — never a silently different game.

## Client
- **S-07-3/2/5 buttons**: tapping any installed card with `installedOptions` picks it (outline) and shows up to 2 buttons in `layout.action` / `layout.action2` (Rez · N credits, Advance · 1 credit, Score, "Take 2 credits · 1 click"); dimmed + engine hint when `reject`. Generalise `pickedInstalled`; rig cards become pickable. Hosted-credit disc (credit colour, ≥ 14 px digits at 640×360, opposite corner from the advancement disc; ICE gets the advancement disc too). PAD note = existing non-blocking notice from `ability_triggered`+`credit_gained`; notices raised under the S-06-5 cover wait until it lifts. `card_rezzed` reuses the rez flip (≤ 300 ms). Memory "…/5" from the view.
- **S-07-4**: run step `success` in the run strip: "Take {gain} credits from Bank Job" + "Access cards"; `access_replaced` end text; breaker buttons add "· Cyberfeeder pays" from `hostedPay`.
- **S-07-1**: columns follow `corpServers` (a removed server's column slides out ≤ 200 ms, non-blocking); names come from the id number. Lobby Back → `OnlineMatch.forget()` sends `leave` first (best effort: offline → lobby lingers until its 2 h TTL).
- **S-07-6 hand (supersedes the hand's Sprint 4 hold-and-slide and Sprint 5 hold-to-read)**: any press on the closed hand strip opens the **hand view** centred on that card: the Sprint 5 carousel made permanent (centre card at zoom size = readable at 640×360, 2 neighbours each side; swipe browses, tap a neighbour centres it). **Tap the centre card** = today's pick (view closes, card outlined, targets lit, tap target plays) — the no-drag path for mouse and for tests. **Long-press (350 ms, no move) the centre card** = lift: the hand view fades out (≤ 120 ms), a board-size ghost follows the finger, targets from `handOptions` light (refused ones dimmed + hint). Release on a lit, legal target → that option's action; on a dimmed one → hint; elsewhere → the ghost flies back (≤ 150 ms) and the hand view returns. Tap outside the view closes it (tap consumed). Back closes it. Discard step keeps the old strip picker; the hand stays put away during runs. Piles, score pills, accessed and installed cards keep hold-to-read. Drag: position set in the `globalpointermove` handler (no tween, no allocation, cached face), hover by box test against `activeTargets`; `pointercancel` (Android edge gesture) = release elsewhere; any new view while lifted cancels the lift (hand indices may have moved). Online: one action in flight as today; the ghost waits on the target until the update/reject.

- **Old online logs** replay under new rules → expired, not corrupted (online play is not live yet).
