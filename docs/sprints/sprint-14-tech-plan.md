## Deck sync (`packages/match/src/saved-decks.ts`, `packages/protocol/src/decks.ts`, `apps/server`)
- **Format 2** = format 1 + `deleted: {id, deletedAt}[]` (tombstones). `parseDeckStore` reads 1 and 2 (a Sprint 13 build sees 2 as `'newer'` = read only, never drops tombstones).
- **One merge rule, pure, shared:** `mergeDeckStores(a, b): DeckStore`: per id, newest of (`updatedAt` | `deletedAt`) wins; tie → tombstone, then smaller JSON. Commutative, associative, idempotent (property-tested). A stale copy can't revive a deleted deck; an edit made *after* the delete does (= "the most recent change wins", AC S-14-2/4). Device clocks are trusted (risk below).
- **Upload check, shared:** `checkDeckUpload(x): DeckStore | UploadProblem` = `parseDeckStore` (must not be `broken`/`newer`) + limits: ≤ 200 decks, ≤ 500 tombstones (server drops the oldest beyond), id ≤ 64, name ≤ 80, ≤ 100 card entries/deck, body ≤ 256 KiB (`MAX_DECK_UPLOAD_BYTES`). Unknown ids / 4 copies are **kept** (a store is not a game). The client never sends what this refuses.
- **Deck code** (`packages/protocol/src/decks.ts`): 12 chars from `CODE_ALPHABET` (no 0/O/1/I/L; 31¹² ≈ 2⁵⁹), shown `KX4P-9MTR-QZ7D`; `makeDeckCode(randomInt)`, `isDeckCode`, `formatDeckCode`; typed input via `normalizeCode`. **The server mints it** (so an unknown code is a wrong guess, never a silent new locker).
- **HTTP API** (CORS for `ALLOWED_ORIGINS`, `OPTIONS` preflight; the code only in the body, never in a URL). `DECKS_API_VERSION = 1`. `POST /v1/decks/new {v, store}` → `200 {v, code, store}`. `POST /v1/decks/sync {v, code, store}` → `200 {v, store}` (merged; client merges it in) · `404 no_decks` · `429 {wait, retryAfterMs}` · `400 bad_store` · `413 too_big` · `400 version`. A refused upload changes nothing stored.
- **Storage:** new SQLite Durable Object `DeckLocker` (one per code, `idFromName(code)`, keys `d:<id>` / `t:<id>`, no expiry) and `GuessGuard` (one per **SHA-256 of the caller's IP**, never the raw IP); wrangler migration tag `v2`. Pure logic in `src/locker.ts` / `src/guard.ts` (clock injected), DO wrappers thin like `do.ts`. Guard: checked before the locker answers (so a locked caller learns nothing); 5 free wrong codes in a row, then wait 60 s × 2ⁿ (cap 1 h); a right code resets; `new` ≤ 10/hour/IP. Test mode only: header `X-Overclock-Test-Ip` picks the "device".
- **Client** (`apps/client/src/deckSync.ts`, key `overclock.deckSync.v1 = {server, code, rev, syncedRev, lockUntil?}`): every local deck write bumps `rev`; merging the server's answer does not. Sync = send the whole store (a few KB, idempotent, so the "offline queue" is just `rev > syncedRev`). Runs on app start (if code or pending), Decks open, 1.5 s after a write, `online`, page visible, every 10 s while Decks is open and visible; failures retry 5/15/60 s. **Nothing is sent while the store has no own deck and no tombstone and there is no code** (AC). The first own deck → `new`. **My deck code** with no own decks also calls `new` (the player asked). Linking = `sync` with the typed code and the local store (Q2 A: merge keeps both); the old code is just forgotten. Status: `saved` "✓ Saved online" (rev = syncedRev) · `saving` · `pending` "Saved on this device · goes online when you're connected" · `none` (no line). Never awaited by a tap; the deck screens never wait on it.

## Online games with own decks (`packages/protocol`, `apps/server/src/room.ts`)
- **Protocol v2** (every `v` = 2; `PING`/`PONG` strings too). `DeckChoice = {identity, cards: Record<cardId, copies>}` (stored-deck shape; parser: ≤ 100 entries, whole 1…200). `create {side, deck?, test?}`; new `pick {deck?}` (joiner); new server `choose {seat}` (joiner: pick now), `deck_refused {problems: DeckProblem[]}` (socket stays open, pick again; on `create` no game is made); `lobby` gains optional `picking: true` (host: "your friend is picking a deck"). Absent `deck` = standard.
- **Room:** `create` validates `deckFromCounts` + `isPlayableDeck(deck, side)`, stores the seed and pick in `meta` (`dealt: false`, test prelude kept in `meta.test`), **no match yet**. `join` seats the guest and sends `seated` + `choose`. `pick` validates, then **deals**: `options = {...ONLINE_OPTIONS, decks?}` (key only for own decks → standard games byte-identical), prelude replayed, snapshot, `dealt: true`, `sync` both. `started()` = both seats **and** dealt (meta without `dealt` = a pre-update room = dealt). Resume while undealt: host `lobby`, guest `choose`. Host `leave` before deal closes the room (as today); guest `leave` before deal frees the guest seat (host back in lobby). Restart/replay already rebuilds from `meta.options`, so own decks survive restarts, reconnects and Leave for now; the client never re-reads its store for a running game.
- **Secrecy:** decks live only in `meta` (server). No message carries `options`/`deck`/`decks` except the sender's own `create`/`pick`; `deck_refused` goes only to the sender. Views already hide R&D/HQ/Stack/Grip; Q3 A = nothing extra at game over.
- **Older apps:** a v1 frame gets `error version` (+ close) from the v2 room; a Sprint 6–13 client decodes any `v ≠ 1` as `version` and shows its built-in "This copy of the game is out of date. Reload the page, or update the app." New clients say **"Update the game to play online"** for `version`. No v1 compatibility mode.

## Risks
- **Sprint branch deploys to the one service:** once `sprint-14` deploys, the Sprint 13 web link and app can't play online (they'll say out of date) until merge. Live Sprint 13 games continue with the new client (`RULES_VERSION` unchanged).
- **Wrong device clock** can make an older edit win (last-write-wins on device time). Accepted; rare.
- **Tombstone cap (500):** a device offline through 500+ later deletes could revive a stale deck. Far beyond real use.
- **Request budget:** poll = 2 DO calls / 10 s per open Decks screen; well inside the free 100k/day.
