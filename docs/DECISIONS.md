- 2026-11-11 — IP check is an automated Vitest test over all card names/text against a short banned-word list (Netrunner, Android, select official card names) — cheap guardrail for rule 3 — manual review only — architect
- 2026-11-11 — Card instances in deck/hand are card definition ids (duplicates = extra copies); starter decks are the 12 unique cards per side plus 3 extra copies to reach the plan's 15 — simplest model for Sprint 0; per-instance ids come when installed cards need their own counters — unique instance ids now, 15 unique cards per side — engine-dev
- 2026-11-11 — Added `invalid_action` reject reason for malformed/unknown actions so `apply` never throws on untyped input (client JSON, replays) — keeps the "never throws" contract — throwing on bad shapes — engine-dev
- 2026-11-11 — Rejection precedence: invalid_action, not_your_turn, no_clicks, deck_empty — simplest order (who, then can you pay, then is it possible) — other orders — engine-dev
- 2026-11-11 — `PlayerView` carries the viewer's `legalActions`; new `viewEvents(player, events)` hides opponent draw ids; `replay(seed, actions)` exported for regression tests — AI must work from the view only; events need the same hidden-info projection as state — AI calling legalActions on full state — engine-dev
- 2026-11-11 — AI stub `chooseAction(view)` returns `Action | null` (null when nothing is legal) instead of `Action` — type-safe under noUncheckedIndexedAccess; nothing-to-do is a real case — throwing — engine-dev
- 2026-11-11 — Engine has no `hasMeaningfulResponse` yet — Sprint 0 has no timing windows; it lands with the first window (runs/rez) — stub that mirrors legalActions — engine-dev
- 2026-11-11 — Root `test` runs `vitest run` per workspace (`npm run test --workspaces --if-present`); tsconfig `types: []` keeps Node/DOM globals out of engine/cards/ai — workspaces without tests (or added later) are tolerated; purity enforced by the type checker too — single root Vitest projects config — engine-dev
- 2026-11-11 — Client renders on demand (redraw only when something changed or a tween is running) instead of an always-on 60fps loop — saves battery on phones and CPU in CI — default Pixi ticker render every frame — ui-dev
- 2026-11-11 — Renderer resolution capped at 2x device pixel ratio; antialias (MSAA) only when DPR < 2 — 3x screens cost 2.25x the pixels for little visible gain; MSAA adds nothing at high DPR — native DPR, always-on antialias — ui-dev
- 2026-11-11 — No full-screen filled layers (backdrop drawn as cheap gradient/grid strokes) — full-screen fills are expensive on software GPUs (sandbox Chromium, low-end phones) — full-screen gradient sprite/filters — ui-dev
- 2026-11-11 — Hit areas and test-hook boxes use the element's logical size, not its glow bounds — glows overlap neighbours and would steal taps / fail overlap tests — Pixi getBounds() including glow — ui-dev
- 2026-11-11 — Cards in flight ignore taps (eventMode none until they land) — avoids zooming/tapping a card mid-animation; the rest of the board stays responsive — lock all input during animation — ui-dev
- 2026-11-11 — Two tween queues: `fx` (event animations, finished instantly by the next action = tap to skip) and `ui` (press feedback, hints, zoom; never skipped) — input never waits for an animation, feedback never vanishes — single queue, input lock — ui-dev
- 2026-11-11 — Pixi ticker minFPS = 4 — big frame gaps advance tweens by real time (up to 250ms) so animations finish on the wall-clock budget on slow devices — default minFPS (tweens slow down on slow frames) — ui-dev
- 2026-11-11 — Client imports @overclock/cards for display-only data (name, text, art key, stats via getCard) — card faces need text the view intentionally omits; no rules are read from it — duplicate display data into PlayerView — architect/ui-dev
- 2026-11-11 — Client has two tsconfigs: tsconfig.json (browser src + unit tests, DOM libs) and tsconfig.node.json (Vite/Playwright configs + e2e specs, Node types) — keeps Node globals out of browser code and DOM out of config files — one mixed tsconfig — ui-dev
- 2026-11-11 — e2e tap timing asserts state update < 100ms and card landed < 600ms (the charter budgets) instead of the tech plan's 300ms — sandbox Chromium software-renders, so 300ms flight timing was flaky; charter budgets are the real requirement — keep 300ms, raise test timeout — architect/ui-dev
